# Context

## Glossary

### 待處理事項

需要收件者採取動作並明確結案的中心項目。前台與後台都可收到待處理事項，已讀不代表已完成。V1 顯示建立時間與排序，但不設定逾期、自動催辦或服務時限。

### 權限申請

前台使用者針對尚未取得的報表分類操作權限或全域管理功能提出的請求，由後台人員審核並處理；處理結果以通知告知申請人。申請人在後台處理前可取消，取消後保留紀錄但不再列為待處理事項。

同一使用者對相同權限目標只能有一張未結案申請；系統須顯示既有申請的狀態，而非建立重複待處理事項。

一張申請單只處理一個目標：一個報表分類及其預覽／匯出／列印權限，或一個全域管理功能。資料庫管理與報表管理各自為獨立目標。

申請表提供選填的「申請原因」欄位；後台拒絕或部分核准時仍必須填寫處理原因。

權限申請可部分核准。系統以完成角色指派後計算出的有效權限作為結果，並保存未核准項目的原因。

拒絕或部分核准權限申請時，後台必須填寫原因；完整核准不強制填寫原因。原因會隨處理結果通知申請人。

角色指派不得授予申請範圍外的權限。若既有角色權限過廣，後台必須先在角色管理建立或調整精準角色，才可完成申請。

### 角色導向核准

權限申請核准時，後台將符合需求的既有角色指派給申請者，不建立使用者特例權限，也不在申請單中直接修改共用角色。沒有合適角色時，後台先在角色管理完成建立或調整，再回到申請單指派角色。

### 後台共用帳號

目前三位人員共用一組後台帳密。通知與待處理事項以後台帳號為收件者，系統不能將認領、處理者或稽核責任歸屬到實際個人。

### V1 通知事件

V1 僅處理四種事件：前台新增報表分類（後台待處理）、前台送出或取消權限申請（後台待處理或結案）、後台完成申請審核（通知申請人）、後台調整角色或使用者角色指派（通知受影響的前台使用者）。其他操作不建立通知，以避免雜訊。

對使用者角色指派的新增或移除，以及其已持有角色的權限異動，皆須通知該使用者。通知須區分有效權限實際新增／移除，與設定已更新但有效權限未變；未指派給該使用者的角色異動不通知。

### 通知中心介面

通知中心提供鈴鐺下拉面板與完整中心頁。下拉面板顯示近期項目、未讀數與通知／待處理頁籤；完整頁保存歷史，並可依已讀／未讀與待處理／已結案篩選及查看處理細節。

前台使用者的角色或權限異動通知不顯示角色名稱，而以有效權限的新增、移除或未變更結果為主；完整頁可查看異動時間與有效權限差異。

鈴鐺的總數為未讀通知與未結案待處理事項之和；通知頁籤以未讀數計算，開啟後可標記已讀；待處理頁籤以未結案數計算，閱讀不改變待處理狀態。
